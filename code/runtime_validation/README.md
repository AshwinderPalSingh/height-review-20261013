# CPU evaluation and worker lifecycle validation

This harness stages exact source, three saved configurations and four checkpoints in a
new folder. `validated_inputs.json` pins their sizes and SHA-256 values. It excludes
generated bytecode and Finder metadata. It refuses changed inputs or an existing output
folder. No historical experiments, configuration snapshots or weights are overwritten.

From the repository root, after installing the CPU evaluation dependencies:

```bash
SMOKE_WORK=$(mktemp -d)
python3 -B code/runtime_validation/build_smoke.py --output "$SMOKE_WORK/artifact"
python3 -B "$SMOKE_WORK/artifact/run_runtime_smoke.py" \
  --artifact "$SMOKE_WORK/artifact" --scratch-parent "$SMOKE_WORK"
```

Use the new environment's Python for both commands. The runner copies source unchanged,
preserves original configs, and derives only `training.cuda=False`, `env.test_size=20`,
`sim.render=False` and `camera.render_checkpoint=None`. It verifies all input hashes
before and after execution. Each stage has a timeout, a JSON result and a complete log.
Outputs are retained in a new scratch directory printed at startup.

The eight stages load compatible VAE/truth, VAE/none and no-VAE/none trained policies
strictly, run two seeded episodes per policy, check exact observation shapes and import
paths, replay headless cases 7/7/8, perform a single-worker train-phase reset/step, check
ordinary and pending-step cleanup of two workers, and run unmodified `test.py` for exactly
episodes 0–19 without config fallback. A train-phase reset/step performs no optimizer
update. These checks do not train a model or re-estimate the paper's performance results.

The three probes are the unchanged probes used for runtime validation. Physics uses a
declared harness-only private PyBullet DIRECT adapter: it rejects shared-memory, GUI and
remote connections before connecting. This changes no source bytes; a pass is scoped to
that adapter. CPU threads are limited, GPU visibility is disabled, and package import
paths/hashes are recorded. There is no no-VAE/truth trained pair in the retained evidence;
the harness does not invent one by changing a trained policy's input flags.

The runner itself installs no software. A complete installation claim additionally
requires the installation receipts and package lock described in the repository README.
This smoke does not verify historical package versions, the Linux NVIDIA image, GPU
execution, full training or independent scientific replication.
